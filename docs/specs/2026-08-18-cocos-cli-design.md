# Замена MCP-моста на CLI: спека

Дата: 2026-08-18. Статус: одобрено по секциям, ждёт ревью целиком.

## 1. Цель и рамки

MCP как транспорт для этого проекта расходует контекст агента впустую и не даёт работать с
несколькими открытыми редакторами. Замена — командная строка поверх собственного протокола.

Цель по приоритету: **сокращение контекста агента**, затем качество и расширяемость. Скорость
работы приоритетом не является.

Рамки:

- MCP удаляется целиком. Обратная совместимость имён и схем не поддерживается.
- Расширение сводится к драйверу: нативный API поверх редактора и движка, без понятия
  «инструмент».
- Вся логика переезжает в CLI.
- Подсистема preview-логов удаляется целиком (§11).
- Внешняя поверхность меняется свободно: количество, имена и границы команд.

Не-цели: поддержка версий Cocos кроме 3.8.x, удалённый доступ, работа без открытого редактора.

## 2. Опорные факты о среде

Все числа измерены на рабочей машине (Windows 11, Node v26.3.1) против двух живых редакторов:
CyberCore на порту 4000 и tl_weedmanager1a на 4001.

**Стоимость нынешнего протокола**

- `tools/list` — 109 834 байта на 89 инструментов, ~28k токенов в каждой сессии до первого
  полезного действия. Медиана инструмента 1025 байт, самый тяжёлый
  `component_set_component_property` — 7134 байта.
- Обёртка `content[0].text` даёт +21.6% поверх полезной нагрузки (1255 байт провода на 1032
  байта `ToolResult`). Причина — двойное кодирование: экранирование каждой кавычки. Доля растёт
  с плотностью кавычек в ответе.
- `scene_dump` на сцене CyberCore — **148 161 байт на 454 узла**, 326 байт на узел, ~37k токенов
  за один вызов.

**Стоимость запуска и обмена**

| Что | Время |
|---|---|
| Голый старт Node | 70–81 мс |
| Round-trip по именованному каналу, тёплый | 0.14 мс |
| Round-trip по TCP на loopback, тёплый | 0.57 мс |
| Вызов через `Editor.Message` (`debug_get_editor_info`) | 1.2 мс |
| Дешёвый вызов scene-скрипта (`scene_query_ready`) | 1.0 мс |
| Тяжёлый вызов scene-скрипта (`scene_get_current_scene`) | 5.1 мс |

Проверенная запись из пяти обращений к драйверу стоит 10–25 мс. Многошаговая оркестрация на
стороне CLI проходит по цене.

**Стоимость библиотек (`require`, минимум из трёх прогонов)**

| Либа | ms | Либа | ms |
|---|---|---|---|
| cac | 3 | zod 3.25 | **7** |
| citty | 6 | zod 4.4 | **67** |
| commander | 13 | valibot | 5 |
| clipanion | 24 | @sinclair/typebox | 187 |
| yargs | 63 | arktype | 217 |
| @oclif/core | **151** | split2, shell-quote | 3 |

Отсюда: `@oclif/core`, `arktype`, `@sinclair/typebox` и апгрейд zod до v4 отклонены по цене
загрузки.

**Граница CJS/ESM.** Редактор работает на **Node v20.15.1** (спрошено у живого редактора через
`debug_get_editor_info`). Node 20 не умеет `require()` ESM-модуля — это появилось в 22.12.
Драйвер собирается `tsc` в CommonJS, поэтому берёт только CJS-зависимости; `p-queue` остаётся на
^6, начиная с v7 он ESM. Пакет `cli/` собирается бандлером и работает на ноде пользователя, там
ESM свободен. По этой причине отклонён `trpc-cli`: он ESM-only и не годится драйверу.

**Именованные каналы на Windows**

`net.createServer` на `\\.\pipe\<имя>` работает. В системе 893 канала, фильтрация по префиксу
мгновенна. Канал освобождается ядром вместе с процессом-владельцем.

## 3. Архитектура

```
агент
  │ shell — единственный интерфейс
CLI              вся логика: политика записи, undo-скобки, оркестрация, диффы, рендер вывода
  │ NDJSON по именованному каналу
драйвер          расширение редактора: выставляет 87 нативных примитивов
  ├ editor.*     58 методов поверх Editor.Message
  └ scene.*      29 методов поверх scene-скрипта
scene script     единственное место, где живёт cc.*
```

Разделение ответственности: драйвер знает, **как** обратиться к редактору и движку; CLI знает,
**что и в каком порядке** нужно сделать. Драйвер не решает, открыта ли сцена, не проверяет
записи, не собирает отчёты.

Следствие для разработки: правка логики перестаёт требовать ручного тыка в Extension Manager.
Драйвер меняется только когда нужен новый примитив движка.

## 4. Драйвер: курируемый нативный API

Поверхность уже существует и уже типизирована. Драйвер выставляет её наружу без изменений.

| Пространство | Методов | Источник типов |
|---|---|---|
| `editor.scene` | 33 | `EditorMessageMaps` |
| `editor.assetDb` | 17 | `EditorMessageMaps` |
| `editor.builder` | 6 | `EditorMessageMaps` |
| `editor.project` | 2 | `EditorMessageMaps` |
| `scene.*` | 29 | `SceneMethods` |

**Итого 87 примитивов.**

**Протокол — JSON-RPC 2.0 через библиотеку `json-rpc-2.0`**, по строке на сообщение, фрейминг
через `split2`, транспорт — сокет. Библиотека даёт корреляцию по `id`, форму ошибок и таймауты;
писать это руками нет причины. Она CommonJS, то есть годится драйверу на Node 20.

```
→ {"jsonrpc":"2.0","id":1,"method":"hello"}
→ {"jsonrpc":"2.0","id":2,"method":"editor.scene.createNode","params":[...]}
→ {"jsonrpc":"2.0","id":3,"method":"scene.dumpSceneNodes","params":[...]}
← {"jsonrpc":"2.0","id":2,"result": <как вернул редактор, без обёрток>}
← {"jsonrpc":"2.0","id":2,"error":{"code":-32000,"message":"...","data":{"pkg","msg"}}}
```

Претензия к MCP касалась двойного кодирования — упаковки всего ответа в экранированную строку
внутри `content[0].text`, что давало +21.6%. Конверт самого JSON-RPC стоит около сорока байт на
сообщение и роли не играет.

`hello` отвечает `{project, projectPath, pid, version, surfaceChecksum}`.

Результаты возвращаются сырыми: `SceneResult` остаётся `SceneResult`. Конвертация в отчёт
(`fromScene` из нынешнего `tools-v2/shared.ts`) переезжает в CLI.

Undo-скобки отдельных операций протокола не требуют: `beginRecording`, `endRecording`,
`cancelRecording` уже входят в `editor.scene`.

**Escape hatch — только `evalInScene`.** Сырой `Editor.Message` наружу не выставляется. Новые
операции над движком, которых нет среди 29 методов, прототипируются через `evalInScene`; то,
что прижилось, переезжает в типизированный метод `SceneMethods`.

**Что меняется в драйвере**

- Резолвер имени в функцию: `EditorApi` — класс с вложенными литералами. Для `ns:"editor"` поле
  `method` содержит `<группа>.<метод>` (`scene.createNode`), для `ns:"scene"` — плоское имя из
  `SceneMethods`. Резолвер отвергает всё, чего нет в списке 87.
- Сериализация операций через `p-queue`: два процесса CLI не должны чередоваться внутри одной
  undo-скобки.
- Обрыв соединения с открытой скобкой вызывает `cancelRecording`.
- `project.profile` читает `Editor.Profile` напрямую и умеет бросать синхронно — оборачивается.

## 5. Поиск инстанса

Расширение на `load()` поднимает `net.createServer`:

- Windows: `\\.\pipe\cocos-cli-<sha1(projectPath)[0:12]>`
- macOS/Linux: `$TMPDIR/cocos-cli/<sha1(projectPath)[0:12]>.sock`

Имя детерминировано от пути проекта. Порт не участвует нигде.

CLI читает пространство имён, фильтрует по префиксу `cocos-cli-`, коннектится к каждому
кандидату и шлёт `hello`. Живость определяется тем, что канал ответил; на POSIX неотвечающий
сокет удаляется как протухший.

Выбор:

- один живой инстанс — берётся молча;
- несколько — `--project <подстрока>` матчится без учёта регистра по имени и по пути; без флага
  или при неоднозначности выход с кодом 3 и списком кандидатов;
- ноль — выход с кодом 3 и текстом, где искали.

`cocos instances` печатает таблицу живых инстансов (`cli-table3`).

Побочный эффект: нынешний HTTP-сервер ставит `Access-Control-Allow-Origin: *` и отвечает 204 на
OPTIONS, то есть любая открытая в браузере страница может слать fetch на `127.0.0.1:4000/mcp` и
управлять редактором. Именованный канал закрывает это по построению.

## 6. CLI: поверхность команд

Команды задачные: одна команда выполняет целую операцию, оркеструя несколько обращений к
драйверу.

```
cocos node create --parent Environment --name Crate --component MeshRenderer --pos 0,1,0
```

Внутри: `beginRecording` → `createNode` → `createComponent` → `setProperty` ×3 → чтение обратно →
`endRecording`. Агент видит одну строку ответа.

Слияния, за счёт которых поверхность сжимается относительно нынешних 86 инструментов:

- `node get` вбирает `get_node_info`, `get_components`, `get_component_info`;
- `scene find` вбирает `find_nodes`, `find_component_owners`, `query_nodes_by_asset_uuid`;
- `node set` вбирает `set_node_property`, `set_node_transform`, `reset_node_property`,
  `reset_node_transform`;
- `node create` вбирает `create_node`, `add_component`, установку трансформа и проверку записи.

Оценка итогового размера — около 57 команд. Точный список составляется в плане реализации.

Группы: `scene`, `node`, `component`, `prefab`, `asset`, `build`, `project`, `log`, `ecs`,
`socket`, `raw` (`evalInScene`), `instances`.

Адресация узлов — путём в сцене. CLI резолвит путь в uuid сам, механика уже есть в
`node-path.ts`. Uuid уходит из поля зрения агента; в дампе CyberCore это 22 630 байт.

Дерево команд строится `commander` из `surface.json`, который шаг сборки генерирует из
дескрипторов команд.

## 7. Вывод и коды выхода

**По умолчанию — текст.** Отступы при выводе в пайп не ставятся никогда: на дампе CyberCore
`JSON.stringify(d, null, 2)` даёт 201 634 байта против 148 161 без отступов, +36% за форматирование.

Деревья рисует `archy`, списки — `cli-table3`. Строка узла: имя, типы компонентов в скобках,
метка `(off)` у неактивного.

```
Editor Scene Background
├─┬ Editor Camera  [EditorCameraComponent]
│ └── SceneViewLight  [DirectionalLight]
├── internal/editor/grid-2d  [MeshRenderer]  (off)
└─┬ Reference-Image-Canvas  [UITransform,Canvas]
  └── Reference-Image  [UITransform,Sprite]  (off)
```

Структурой выражены: `path` (путь от корня), `parentUuid` (вложенность), `childCount` (наличие
потомков), `activeInHierarchy` (вложенность плюс `(off)` у предка). `className` выброшен — для
`cc.*` он выводится из `type`. Результат на сцене CyberCore: **17 345 байт против 148 161, в 8.5
раз меньше**, 38 байт на узел против 326.

Собственный рендерер отступами дал бы 16 458 байт — на 5% меньше. Это не окупает своей ветки
кода: экономия контекста стоит того на порядке величины, а не на пяти процентах.

Отчёт о записи — одной строкой:

```
ok  Sprite.color = #ffffff  verified persisted=true undo=1
```

Трёхзначность `persisted` (`true` / `false` / `null` — никто не смотрел) и различие каналов
`editor`/`live` из нынешнего `WriteReport` сохраняются в текстовой форме и в `--json`.

**Флаги вывода**

- `--json` — полная структурная форма на stdout;
- `--uuid` — показать uuid в деревьях и списках;
- `--quiet` — только код выхода.

Разделение потоков: на stdout идёт полезная нагрузка — дерево, список, строка отчёта или JSON
при `--json`. На stderr идут поясняющее сообщение, предупреждения и текст ошибки. Так stdout
остаётся пригодным для `jq` и для конвейера.

**Коды выхода**

| Код | Значение |
|---|---|
| 0 | успех |
| 1 | операция отказала |
| 2 | ошибка употребления: неизвестная команда, плохой флаг |
| 3 | редактор не найден или неоднозначен |
| 4 | обрыв протокола, драйвер не ответил |

## 8. Режим `--stdin` и undo

`cocos --stdin` читает по команде на строку, разбирает кавычки через `shell-quote`, держит одно
соединение на весь поток и печатает JSONL — одну строку ответа на команду. Останов на первой
ошибке по умолчанию, `--keep-going` отменяет.

**Undo-скобка открывается на каждую пишущую команду**, `--no-undo` отключает. В режиме `--stdin`
доступна одна скобка на весь поток.

## 9. Раскладка репозитория и сборка

npm workspaces, три пакета:

| Пакет | Содержимое | Сборка |
|---|---|---|
| `driver/` | расширение для `extensions/`, самодостаточное: `editor-api`, `scene-script-client`, `scene/`, сервер канала, панель | `tsc`, CommonJS |
| `cli/` | всё остальное: команды, чистые модули, рендер, разбор аргументов | `tsup`, один файл |
| `shared/` | только типы: контракт сцены, типизация `EditorMessageMaps`, форма протокола | `tsc` |

`shared/` не содержит рантайма. Компилятор ловит попытку `cli/` импортнуть модуль из `driver/`.

**Зависимости `cli/`** — сборка бандлером, ESM допустим:

| Либа | Тип | Зачем |
|---|---|---|
| `commander` | ESM | дерево команд, разбор флагов, генерация `--help` |
| `json-rpc-2.0` | CJS | клиентская сторона протокола |
| `zod` 3.25 | CJS | валидация аргументов команд |
| `split2` | CJS | фрейминг по строкам поверх сокета |
| `shell-quote` | CJS | разбор строки `--stdin` в argv |
| `archy` | CJS | рендер деревьев |
| `cli-table3` | CJS | рендер таблиц |
| `picocolors` | CJS | цвет, гаснет вне TTY |
| `ora` | ESM | спиннер на долгих операциях при TTY |
| `@pnpm/tabtab` | CJS | генерация completion-скриптов bash/zsh/fish |
| `picomatch` | CJS | маски путей в `asset ls` |
| `fastest-levenshtein` | CJS | подсказка при опечатке в имени команды |
| `microdiff` | ESM | сравнение нормализованных сериализованных значений |
| `lodash.get` | CJS | доступ по пути в токенах `{{0.data.uuid}}` |
| `zod-to-json-schema`, `tsup` | — | генерация `surface.json` и сборка (devDep) |

**Зависимости `driver/`** — `tsc` в CommonJS на Node 20, только CJS:

| Либа | Зачем |
|---|---|
| `json-rpc-2.0` | серверная сторона протокола |
| `split2` | фрейминг по строкам |
| `p-queue` ^6 | сериализация операций (v7+ уже ESM) |

Драйвер валидирует ровно одно: что имя метода есть в списке 87. Схемной библиотеки ему не нужно —
примитивы типизированы через `EditorMessageMaps` и `SceneMethods`.

Удаляется `@modelcontextprotocol/sdk`.

**Что остаётся самописным**

- Доменное знание про Cocos, где библиотеки не существует: `property/`, `prefab-json`,
  `prefab-value`, `prefab-linkage`, `reference-scan`, `reference-projection`, `node-path`,
  `node-type`, `asset-query`, `asset-json`, `ecs-census`, `missing-scripts`, `scene-signature`.
  Переезжает как есть, уже покрыто тестами.
- Поиск канала: `fs.readdirSync` по пространству имён, фильтр по префиксу, `net.connect`.
  Библиотеки для перечисления именованных каналов Windows нет.
- Резолвер `ns.method` в функцию: таблица из 87 записей.
- Нормализация сериализованного значения перед `microdiff` — обход `__id__` и `__uuid__`, это
  уже делает `plainSerialized`.
- Разбор токена `{{0.data.uuid}}` в `batch-plan`; доступ по пути внутри токена берёт `lodash.get`.
- Рендер `WriteReport` в строку: формат доменный.

Имя бинаря — `cocos`. На PATH машины оно свободно, как и `cocos-cli` и `ccm`. В реестре npm все
три имени заняты чужими пакетами, поэтому публикация потребует scope; на локальную глобальную
установку это не влияет.

Установка CLI — `npm i -g` из `cli/`. Рассинхрон версий ловится сравнением `surfaceChecksum` из
`hello` со своим; при расхождении CLI печатает обе версии и требует переустановки.

## 10. Тестирование

Протокол из двух операций делает драйвер подделываемым. Тест поднимает фальшивый драйвер с
заготовленными ответами и прогоняет команду целиком: разбор флагов, оркестрацию, ретраи, сборку
отчёта, рендер вывода, код выхода.

Охват меняется качественно. Сегодня тестами покрыты только чистые модули, всё выше проверяется
живьём. После переезда живьём остаётся проверяться только драйвер — 87 методов, которые сами по
себе почти не содержат логики.

Правило «случай попадает в набор только если мутация продакшн-кода его роняет» сохраняется.
Тесты на проводку, состояние редактора и UI по-прежнему не пишутся.

## 11. Что удаляется

**Файлы:** `source/server.ts`, `source/preview-console-client.ts`, `source/preview-log-store.ts`.

**Инструменты:** `debug_get_preview_logs`, `debug_clear_preview_logs`,
`debug_get_performance_stats` (последний всегда возвращает `fail` с единственным советом читать
preview-логи, то есть после их удаления остаётся пустой заглушкой).

**Прочее:** зависимость `@modelcontextprotocol/sdk`; `ctx.logs` из `ToolContext`; настройки
`port`, `autoStart`, `maxConnections` (`maxConnections` уже мёртв — нигде не читается, а
`getStatus()` отдаёт `clients: 0` константой); сообщения `start-server` и `stop-server` в
`package.json`.

**Правки описаний:** `debug_project_logs` и `project_run_project` ссылаются на preview-логи.

**Панель** сводится к имени канала, имени проекта и статусу.

**`CLAUDE.md` переписывается целиком:** процедура чекпоинта, схема слоёв, таблица ключевых
файлов и правило про чистые функции описывают архитектуру, которой больше не будет.

## 12. Порядок работ

Большой взрыв: MCP сносится сразу, переезд идёт одним заходом, без переходного слоя и двойной
поддержки. Разбиение на шаги — работа плана реализации.

## 13. Что проверяется живым прогоном

Компилятор и тесты этого не закрывают:

1. Вкладывается ли собственная структурная запись редактора (создание узла) внутрь открытой
   скобки `beginRecording`/`endRecording`. От ответа зависит обещание «один Ctrl+Z на команду»
   для `node create`. Нынешний `CLAUDE.md` фиксирует, что сейчас получается два шага.
2. Поведение `beginRecording`, `endRecording`, `cancelRecording` — они резолвятся через

## 14. Приложение: воспроизведение измерений

Размер поверхности MCP:

```bash
curl -s -X POST http://127.0.0.1:4000/mcp -H 'Content-Type: application/json' -H 'Accept: application/json, text/event-stream' -d '{"jsonrpc":"2.0","id":1,"method":"tools/list"}' | wc -c
```

Размер дампа сцены — тот же запрос с `{"method":"tools/call","params":{"name":"scene_dump","arguments":{}}}`,
длина `result.content[0].text`.

Стоимость `require` библиотеки:

```bash
node -e "const t=process.hrtime.bigint();require('commander');console.log(Number(process.hrtime.bigint()-t)/1e6)"
```
